# Manual validation of milestone M4 (MongoDB, Elasticsearch, Redis)

Guide to validate M4 on **macOS** and **Windows** (and another Linux desktop if at hand). Allow about 3 h per OS: five servers, three engine families, a console and an edit path each. Section 3 is the checklist; section 4 says what was checked on Linux in the real app and how, section 5 the measurements, section 6 the bugs found (fixed, and open), section 7 what could not be verified here, section 8 what only macOS and Windows can tell.

M4 exit criterion (`docs/PLAN.md`, `docs/analysis/NOSQL.md`): MongoDB, Elasticsearch / OpenSearch and Redis / Valkey can be connected, browsed, queried in their own language and edited without overwriting someone else's work, with the same safety as the SQL engines (read-only enforced in the backend, dangerous operations confirmed with their effect, edits previewed, journaled and revertible), and where an apply cannot be atomic the preview says so and why. Requirements: SPEC §5.9 (F-160 to F-175).

The M0 to M3 checklists still apply to the SQL engines.

## 1. Prerequisites

Same toolchain as M3 (`docs/validation/M3.md`, section 1). Engines, from the repository root:

```bash
dev/tls-certs.sh                                                   # once: throwaway CA + localhost certificate
docker compose -f dev/compose.yml up -d mongo mongo-standalone redis valkey
docker compose -f dev/compose.yml --profile search up -d elasticsearch opensearch   # ~1 GB of RAM each
```

|---|---|---|---|
| **mongo-rs** | MongoDB 7.0, single-node replica set `rs0` | `mongodb://localhost:57017/m4?replicaSet=rs0` | no authentication; transactions |
| **mongo-sa** | MongoDB 7.0 standalone | `mongodb://yadbe@localhost:57018/m4s?authSource=admin` | password `yadbe-test-pw`; no transactions |
| **redis** | Redis 8.2 (RedisJSON) | `redis://yadbe@localhost:56379/0` (TLS: `rediss://…:56380`) | password `yadbe-test-pw` |
| **valkey** | Valkey 8.1 | `redis://yadbe@localhost:56381/0` | password `yadbe-test-pw` |

| **opensearch** | OpenSearch 2.19, plain HTTP, security off | `http://localhost:59201` | — |

Paste each URL in **New connection → Connection string → Fill the form**, leave the password empty (it is asked at connect), name the connection as in the table. For the SSH checks, also **redis-ssh** and **mongo-ssh** (`…&directConnection=true`) through `dev/ssh-test.sh` (Linux) or any SSH server that reaches the engines.

Data (the shell clients of the containers; throwaway):

```bash
docker exec yadbe-test-engines-mongo-1 mongosh --port 57017 --quiet --eval '
  const d = db.getSiblingDB("m4"); d.dropDatabase(); const docs = [];
  for (let i = 1; i <= 1200; i++) docs.push({ _id: i, sku: "sku-" + i, qty: NumberInt(i % 7),
    price: NumberDecimal((i * 1.25).toFixed(2)), status: ["paid","shipped","new"][i % 3],
    at: new Date(Date.UTC(2026, 0, 1) + i * 3600000), tags: ["a" + (i % 5)],
    customer: { name: "c" + (i % 40), vip: i % 10 === 0 } });
  d.orders.insertMany(docs); d.orders.createIndex({ status: 1 });
  d.slow.insertMany(Array.from({ length: 50 }, (_, i) => ({ n: i })));
  d.createView("paid", "orders", [{ $match: { status: "paid" } }])'
docker exec yadbe-test-engines-mongo-standalone-1 mongosh -u yadbe -p yadbe-test-pw --authenticationDatabase admin --quiet --eval '
  const d = db.getSiblingDB("m4s"); d.dropDatabase();
  for (let i = 1; i <= 30; i++) d.items.insertOne({ _id: i, name: "item " + i, n: NumberLong(String(i * 1000)) })'
R="docker exec -i yadbe-test-engines-redis-1 redis-cli -a yadbe-test-pw --no-auth-warning"
for i in $(seq 1 30); do echo "HSET m4:user:$i name user$i age $((20+i)) city c$((i%5))"; done | $R >/dev/null
for i in $(seq 1 2000); do echo "SET m4:cache:$i v$i"; done | $R >/dev/null
$R SET m4:greeting "hello world"; $R RPUSH m4:list a b c d; $R SADD m4:set x y z
$R ZADD m4:rank 1 one 2 two 3 three; $R XADD m4:events '*' kind login user 1
$R JSON.SET m4:doc '$' '{"a":1,"b":[1,2,{"c":true}]}'
```

Elasticsearch and OpenSearch: an index `m4-orders` of 1,200 documents (`sku` keyword, `qty` integer, `price` scaled_float, `status` keyword, `at` date, `big` long above 2^53, `note` text) and an alias `m4-all`, loaded with one `_bulk` request (`?refresh=true`) on each server.

Drop it all afterwards: the `m4` / `m4s` databases, `FLUSHDB` on database 0 of both key-value servers, `DELETE /m4-orders` on both search servers, `docker compose … --profile search stop`.

## 2. Running the app

The checklist with the debug build that carries the production CSP (`pnpm tauri build --debug --no-bundle`) and the web inspector open (right click → Inspect: CSP violations, console errors), the measurements with the release build. `⌘` on macOS = `Ctrl` elsewhere. **MG**, **RD**, **ES** mark the family a line applies to (MongoDB, Redis / Valkey, Elasticsearch / OpenSearch).

## 3. Checklist

### Connect and explore (F-160, F-162, F-163, F-166, F-167, F-170, F-171)

- [ ] **MG** Connect **mongo-sa** — Expected: "Password for mongo-sa", connected; explorer `m4s` → `items`. **mongo-rs** — no prompt; `m4` → `orders`, `paid` *view*, `slow`; expand `orders`: sampled fields with their types, indexes.

- [ ] **ES** Connect **es** (password) and **opensearch** — Expected: Indices (`m4-orders 1,200 docs`), Data streams, Aliases (`m4-all`), Index templates; the status bar names the product and version.

### Data tabs (F-163, F-167, F-171)

- [ ] **MG** Double-click `orders` — Expected: grid 1–100, "≈ 1,200 documents", "Pages follow _id"; Next → 101–200; filter `{ "status": "paid", "qty": { "$gte": 5 } }`, sort `{ "qty": -1, "_id": 1 }`, Find, Count → "114 documents match", "Pages skip (sorted on another field)"; **Documents** view: a tree with `DECIMAL` / `DATE` badges.
- [ ] **RD** Open `m4:user:1`, `m4:rank`, `m4:events`, `m4:doc` — Expected: one viewer per type, time to live, length, encoding, memory.
- [ ] **ES** Double-click `m4-orders` — Expected: "Point in time" (Elasticsearch) or "from / size: pages stop at document 10,000" (OpenSearch); query string `status:paid AND qty:>=5` + Enter → 114 documents; sort `qty`, page 2 → 101–114; `big` shows `9007199254740994` exactly.

### Consoles (F-164, F-168, F-172, F-161)

- [ ] **MG** In a mongosh tab: `db.scratch.insertMany([{ a: 1 }, { a: 2 }, { a: 3 }]); print('inserted ' + db.scratch.countDocuments()); const r = db.scratch.deleteMany({}); print('deleted ' + r.deletedCount); db.scratch.countDocuments()` `⌘↵` — Expected: "inserted 3" in **Messages** while the script waits, then "Run deleteMany? … 3 documents" → **Run it** → result `0`, messages "inserted 3", "deleted 3".
- [ ] **MG** `print('started'); db.slow.find({ $where: 'sleep(200) || true' }).toArray()` → Cancel after 2 s — Expected: "The script stopped / Cancelled." within a second, the operation gone from `db.currentOp()`.
- [ ] **MG** Completion: `db.ord` + `⌃Space` → `orders`; `db.orders.find({ stat` → `status`.
- [ ] **RD** `HGETALL m4:user:2`, then `KEYS m4:user:*` and `DEL m4:cache:1 … m4:cache:11` in one run — Expected: "Run 2 dangerous commands?" with "Walks all 2036 keys…" and "Deletes 11 keys; 11 of them exist now."; Cancel → nothing ran. A Lua busy loop (`EVAL "local i=0 while i<200000000 do i=i+1 end return i" 0`) then a `SET`, Stop while it runs — Expected: the loop's reply, "1 line not run".
- [ ] **RD** Completion: `HGETA` + `⌃Space` → `HGETALL`; `HGETALL m4:user:1` → the scanned keys.
- [ ] **ES** `GET /m4-orders/_search` with `{ "query": { "term": { "status": "new" } }, "size": 3 }` — Expected: 3 hits, "400 documents"; `DELETE /m4-orders` — Expected: "Send a dangerous request? … Deletes 1 index(es) and their 1 200 documents" → Cancel. A slow `script_score` search, then Stop — Expected: "Cancelled." at once; on the server the task is marked cancelled (`GET _tasks?actions=*search*&detailed`, `X-Opaque-Id: yadbe-…`).
- [ ] **ES** Completion: `GET /m4` → `m4-all`, `m4-orders`; inside a `term` → `status`.

### Edits, conflicts, journal (F-165, F-169, F-173)

- [ ] **MG** **mongo-rs** `orders`: double-click `sku` of a row and `qty` of another, Keep change; from `mongosh` change the second document's `qty`; **Review and apply** — Expected: "2 operations run in one transaction…", `$expr` guards; Apply → "A document changed on the server … the transaction was aborted and nothing was applied" with You saw / Server now / Yours. **Keep mine** → Resolve → the preview now checks the server's value → Apply. Journal → the entry → **Revert this change set** → Revert (2) — Expected: both documents as before the apply.
- [ ] **MG** **mongo-sa** `items`: two edits, change the second document from `mongosh`, Review — Expected: "Not atomic: this server is a standalone MongoDB, which has no multi-document transactions…"; Apply → "the apply stopped there. The change before it was applied (one by one…) and is in the journal"; Take theirs; revert the first from the journal.
- [ ] **RD** `m4:user:1`: change `age`, change it from `redis-cli` meanwhile, **Preview commands** (`WATCH` … `MULTI` / `HSET` / `EXEC`) → Apply — Expected: "Someone changed these keys since you read them: nothing was applied"; Keep mine → Apply → applied. Explorer `cache` → **Delete every key here…** — Expected: "2,000 keys match now… deleted by batches of 500 keys, each batch in one transaction… the whole is not one transaction, because…"; Delete → "2,000 keys deleted"; Journal → revert both (the 2,000 keys come back from their snapshots).
- [ ] **ES** `m4-orders`: row menu **Edit the document…** (change `status`), another row **Delete the document**; change that one from `curl` (`_update`); Review — Expected: "Applied one document at a time, not all or nothing: Elasticsearch has no transaction across documents…", `if_seq_no` / `if_primary_term`, `refresh=wait_for`; Apply → "Stopped after 1 of 2 changes" with your version and the server's; Keep theirs; revert the first from the journal. - [ ] **All** Edit → **Read-only** on, Save, then: **MG** `insertOne` in a script → "This connection is read-only: insertOne may change data… Nothing was run." at its line; the collection tab says "Read-only connection: documents cannot be changed"; **RD** `SET` → "This connection is read-only: SET changes data. ## 4. What was checked on Linux, and how

The real app was driven in the Linux container (Ubuntu 24.04, WebKitGTK 2.52.6, Xvfb with `WEBKIT_DISABLE_COMPOSITING_MODE=1`): the debug build with the production CSP (`pnpm tauri build --debug --no-bundle`), through `tauri-driver` + `WebKitWebDriver` with plain W3C WebDriver requests from a Node script (session scratch space, not committed), with the workarounds of `docs/validation/M3.md` section 4 (synthetic `pointerdown` before clicks outside grids, text inserted rather than typed). Text was put in the editors by a cancelable `beforeinput` over the selection (what typing does), not by `execCommand('insertText')`, which makes WebKit itself replace the selection and raises a CSP report of its own (section 6). In-page listeners recorded CSP violations (`securitypolicyviolation`, with their target), console errors and warnings, uncaught errors and rejections on every scenario. The GTK file chooser of the exports was driven with `xdotool`. Every write was verified from `mongosh`, `redis-cli` / `valkey-cli` or HTTP requests to the search servers.

Engines: MongoDB 7.0.48 (single-node replica set, and standalone with authentication), Redis 8.2.11 (RedisJSON), Valkey 8.1.11, Elasticsearch 9.1.0 (HTTPS with the dev CA, basic authentication), OpenSearch 2.19.1 (plain HTTP, security off); for the suites also PostgreSQL 16.15 (native), SQL Server 2022 (16.0.4325.4) and MySQL 8.4.13 in Docker, `dev/mtls.yml` (PostgreSQL 16.16, MySQL 8.4.13, MongoDB 7.0 requiring a client certificate) and `dev/ssh-test.sh` (OpenSSH on 2222 / 2223 / 2224).

Secrets: no Secret Service in the container, so every password was typed in the app's prompt and kept for the session only.

## 6. Bugs and gaps found

Fixed by this task (each with a test that failed before the fix):

1. **Exporting a whole MongoDB, search or key-value result failed** with "This result is no longer available" (CSV, JSON Lines… alike), while its preview worked: a whole-result export looked the result up among the SQL statements only. Found exporting a collection page as JSON Lines in the real app; the M4-9 test had built its own source instead of going through the export manager. Fixed in `src-tauri/src/export/source.rs`, test in `tests/export.rs`.
2. **Typing over a selection in any editor raised a blocked `style-src-attr` CSP report** (M4-3 notes). Cause: WebKit replaces selected text in a contenteditable by deleting it, then inserting the typed text with the deleted text's style carried as a `style` attribute (the trace showed `style="color: rgb(124, 58, 237)"` on a highlighted line); CodeMirror itself only uses the CSSOM, which the CSP allows. Fixed without touching the CSP: `src/ui/editorCsp.ts` takes plain typing over a non-empty selection through CodeMirror's input handlers. In the debug build: 1 report per try before (3 tries), 0 after (3 tries), and none in any editor during the scenarios of section 4.
3. **A mongosh script's operations reached the statement log unmasked** (a `createUser`'s `pwd`, a `password` field), while the history masked them (rule 4). Fixed in the document gate; test in `tests/mongosh.rs`.

Done from the M4-9 leftovers: mongosh `print` output streamed while the script runs (`mongo-script-output`); the statement log of script / request operations audited (item 3; the search and key-value gates log only yadbe's own requests and commands, displayed without credentials); the Playwright tests that failed under load and the decimal timing test made sturdy at their cause.

Open, for the owner to decide (none is a safety issue):

4. The export from a collection or index tab writes **the page shown** (100 documents), titled "Export the result", where a SQL table tab exports the whole table under its filter. A whole-collection / whole-index export (by pages, as `TableExportRows` does) would be the consistent behaviour.
5. Cancelling a search: the UI says "Cancelled." at once and the task is flagged cancelled on the server, but Elasticsearch checks the flag between documents: a heavy per-document script ran on for about 35 s. A note in the cancelled state ("the server may finish the current step") would avoid surprise.
6. The revert dialog of a Redis change set over 500 keys says both "in one checked transaction" and "it runs as 4 transactions of up to 500 keys".
7. Cosmetic: at 1280 px the engine choice of the connection dialog overflows (a horizontal scrollbar under the form); the collection tab's toolbar wraps "Add document / No changes" in the Documents view and the read-only note on three lines; the Elasticsearch danger text writes "1 200 documents" (space separator, not the locale's) and "index(es)"; the toast after an apply reads "Changes applied" for MongoDB and Redis, "1 document changed" for search; the journal filter says "All tables" and "Search tables, values…" for collections, indices and keys.
8. Harness note, not an app bug: `document.execCommand('insertText')` over a selection (a test harness, or an extension) still makes WebKit apply the deleted text's style and report it; the app's own input paths (typing, paste, drop, completion) do not go there. An IME composition over a selection is left to the browser and may still raise the report.

## 7. Not verifiable here

macOS (WKWebView) and Windows (WebView2): QuickJS (`rquickjs`) has only ever been built and run on Linux; the OS keychains for the new secret kinds (MongoDB, Redis and Elasticsearch passwords, API keys and bearer tokens stored as the connection's password); native file dialogs of the JSON Lines export; the console shortcuts with `⌘`. Here: no Secret Service (every secret was session-only); `mongodb+srv` on real DNS, sharded clusters, X.509 authentication, Redis Cluster / Sentinel (not supported), Redis < 7, Elasticsearch 7 / 8, OpenSearch 1 / 3 and OpenSearch with security; a client certificate to Redis and to Elasticsearch; the Elasticsearch SSH tunnel in the real app (Redis and MongoDB were checked); a write that times out on Elasticsearch; Valkey's console dangers (same code as Redis). Only on the mock and in the integration tests: data streams, closed and write-blocked indices, RedisJSON and stream edits, time series and capped collections.

## 8. Checklist for the owner on macOS and Windows

Run section 3 on both, with the OS keychain available. In addition:

- [ ] **Build**: `pnpm tauri build` succeeds (QuickJS is C compiled by `cc`: Xcode command-line tools on macOS, MSVC on Windows), then a mongosh script with `print`, a cursor, `ObjectId()` and `ISODate()` runs; an infinite loop `while (true) {}` is stopped by Cancel and by the statement timeout.
- [ ] **Keychain**: "Remember password" for **mongo-sa**, **redis**, **es**; an Elasticsearch connection with an API key; restart; connect — Expected: no prompt, and the secret in the keychain under `dev.tropico.yadbe`, not in `yadbe.db`.
- [ ] **TLS with the system roots**: a MongoDB Atlas (`mongodb+srv://`, TLS on by itself), a managed Redis (`rediss://`) and an Elastic Cloud deployment, all without a CA file — Expected: connected, certificate checked.
- [ ] **TLS with the dev CA**: **es** with `dev/certs/ca.crt`; the same without the CA and without "Do not check the certificate" — Expected: a typed TLS error.
- [ ] **Editors**: type over a selection in the mongosh, Redis and search consoles and in the JSON editor of a search document, with the web inspector open — Expected: no CSP report; with an IME (Japanese or dead keys on a Mac keyboard) over a selection — note what happens.
- [ ] **Exports**: JSON Lines of a collection page and of hits through the native save dialog; open the file — each line a whole document.
- [ ] **Shortcuts**: `⌘↵` (run; the request under the cursor in the search console), `⌘⇧↵` (the line under the cursor in the Redis console), `⌘.` (cancel), `⌃Space` (completion; on macOS it switches the input source by default: check it reaches the editor), `F2` in the documents view.
