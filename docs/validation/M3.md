# Manual validation of milestone M3 (V1)

Guide to validate M3 on **macOS** and on **NixOS** (or another Linux desktop) before the V1 release. Allow about 3 h per OS (four engines, SSH and TLS servers). The cross-feature scenarios come first: they are where the M3 pieces meet. Section 4 lists what was checked on Linux in the real app and how, section 5 gives the performance measurements, section 6 the bugs found, section 7 what could not be verified here.

M3 exit criterion (`docs/PLAN.md`): MySQL / MariaDB is supported, data can be navigated through its relations and edited without overwriting someone else's work, queries are kept in a library, remote databases behind SSH are reachable, and the daily rough edges found at the end of M2 are gone.

Not in this milestone's validation: Entra ID (M3-13) and distribution (M3-14), both blocked on external means. The M0, M1 and M2 checklists still apply.

## 1. Prerequisites

Same toolchain and engines as M2 (`docs/validation/M2.md`, section 1), plus MySQL, an SSH server and the servers that require a client certificate. From the repository root:

```bash
dev/tls-certs.sh                                     # once: throwaway CA + localhost certificate
docker compose -f dev/compose.yml up -d -V           # PostgreSQL 55432, SQL Server 51433, MySQL 53306
                                                     # (-V once: the MySQL user gets PROCESS + performance_schema)
docker compose -p yadbe-mtls -f dev/mtls.yml up -d   # PostgreSQL 55433 and MySQL 53307 that require a client certificate
sudo dev/ssh-test.sh /tmp/yadbe-sshd                 # Linux only: OpenSSH on 2222 (tunnel), 2223 (jump host), 2224 (no forwarding)
                                                     # macOS: use any SSH server you can reach that forwards to the engines
```

Fixtures, one schema (PostgreSQL), database (SQL Server) or database per fixture (MySQL), and SQLite files:

```bash
FX=src-tauri/tests/fixtures
export PGPASSWORD=yadbe-test-pw; PSQL="psql -h localhost -p 55432 -U yadbe -d yadbe_test -v ON_ERROR_STOP=1 -q"
$PSQL -c "create schema m3; create schema m3fk; create schema m3fk2; create schema m3j; create schema m3re; create schema m3ef"
sed 's/{s}/m3/g' $FX/edit_postgres.sql | $PSQL
sed 's/{s2}/m3fk2/g; s/{s}/m3fk/g' $FX/fk_postgres.sql | $PSQL
sed 's/{s}/m3j/g' $FX/journal_postgres.sql | $PSQL
sed 's/{s}/m3re/g' $FX/result_edit_postgres.sql | $PSQL
sed 's/{ef}/m3ef/g' $FX/ef_postgres.sql | $PSQL
$PSQL -c "insert into m3.items(sku, qty, price) select 'sku-' || g, g % 5, g + 0.5 from generate_series(1, 40) g;
  create table m3.renme (id int primary key, v text); insert into m3.renme values (1, 'a'), (2, 'b');
  create table m3.imp (id int primary key, name text not null, price numeric(10,2), day date)"
# SQL Server: database m3db with the edit, fk, journal, result_edit and ef fixtures (each file batch by batch)
MS="docker exec -i yadbe-test-engines-mssql-1 /opt/mssql-tools18/bin/sqlcmd -C -I -b -S localhost -U sa -P Yadbe-test-pw1"
$MS -Q "CREATE DATABASE m3db"
for f in edit fk journal result_edit ef; do
  docker cp $FX/${f}_mssql.sql yadbe-test-engines-mssql-1:/tmp/$f.sql; $MS -d m3db -i /tmp/$f.sql
done
$MS -d m3db -Q "CREATE TABLE dbo.renme (id int PRIMARY KEY, v nvarchar(20)); INSERT INTO dbo.renme VALUES (1, N'a')"
# MySQL: databases yadbe_m3 (edit), yadbe_m3fk + yadbe_m3fk2, yadbe_m3j, yadbe_m3re, yadbe_m3ef (root: yadbe-test-root)
MY="docker exec -i yadbe-test-engines-mysql-1 mysql -uroot -pyadbe-test-root"
for d in yadbe_m3 yadbe_m3fk yadbe_m3fk2 yadbe_m3j yadbe_m3re yadbe_m3ef; do $MY -e "create database $d"; done
$MY yadbe_m3 < $FX/edit_mysql.sql
sed 's/{db2}/yadbe_m3fk2/g; s/{db}/yadbe_m3fk/g' $FX/fk_mysql.sql | $MY yadbe_m3fk
$MY yadbe_m3j < $FX/journal_mysql.sql; $MY yadbe_m3re < $FX/result_edit_mysql.sql; $MY yadbe_m3ef < $FX/ef_mysql.sql
# SQLite
sqlite3 m3.db < $FX/edit_sqlite.sql; sqlite3 m3.db < $FX/journal_sqlite.sql
sqlite3 fk.db < $FX/fk_sqlite.sql; sqlite3 ef.db < $FX/ef_sqlite.sql
```

Connections: **pg**, **ms** (database `m3db`), **my** (database `yadbe_m3`), **sl** (`m3.db`) as in M2; **pg-ssh** (pg through the SSH server, password auth) and **my-ssh-jump** (my through the SSH server with the agent, via the jump host with a key file); **pg-mtls** (`localhost:55433`, user `yadbe_client`, no password, client certificate `src-tauri/tests/fixtures/tls/client.crt` with the encrypted key `client.encrypted.key`, passphrase `yadbe-test-passphrase`) and **my-mtls** (`localhost:53307`, user `yadbe_x509` / `yadbe-x509-pw`, key `client.pkcs8.key`). Keep a second client open on each engine: every "verify" below means *from that client*.

Drop it all afterwards: `drop schema m3, m3fk, m3fk2, m3j, m3re, m3ef cascade`, `DROP DATABASE m3db`, the `yadbe_m3*` databases, the SQLite files; `dev/ssh-test.sh stop`, `docker compose -p yadbe-mtls -f dev/mtls.yml down -v`.

## 3. Checklist

### Edit a query result, someone else changes the row, journal, revert (F-087, F-089, F-090) — PG, MS, MY, SL

- [ ] `select id, name, price from m3re.items order by id` (**MY** `yadbe_m3re.items`, **MS** `re.items`) — Expected: footer "Editable m3re.items", its hover says why.
- [ ] Change `name` of rows 1 and 2; from the other client `update … set name = 'theirs' where id = 1`; `⌘S` → Preview SQL (`WHERE "id" = 1 AND "name" = 'one'`) → Apply — Expected: "1 row was changed by someone else", nothing applied, the row shows When read / Yours / Now on the server. **Keep mine** → Resolve → the preview now checks `'theirs'` → Apply → both rows changed (verify).
- [ ] Sidebar **Journal**: the change set on top ("2 updated"), click it — Expected: statements run and inverse statements; **Revert this change set…** → preview → **Revert (2)** — Expected: "Change set reverted", rows back (verify), entries "revert of #1" and "reverted".
- [ ] Revert again after changing the row from the other client — Expected: refused, "1 row changed since this change set", nothing changed.
- [ ] Re-run the query with a pending change — Expected: "Discard 1 pending change?".

### Sort / filter a result, then edit (F-065, F-087) — PG, MY

- [ ] Same result with a pending change: click the `price` header twice — Expected: footer "Read-only · 1 pending change waits until the sort and filter are cleared", hover "The rows are sorted or filtered…", double-click on a cell opens nothing. Third click (stored order) — Expected: editable again, the change still pending on its row.
- [ ] `⌘⇧F`, value `th` — Expected: "1 of 4 rows", read-only; Clear sort and filter, Hide the filter.
- [ ] `⌘`+click the `price` header — Expected: aggregates Count 4, Sum 12, Avg 3, Min 1.5, Max 4.5 (exact decimals). `⌘⇧D` — row detail panel, one line per column.

### Objects with an open tab and a pin (F-024 to F-027) — PG, MS

- [ ] `⌘K` `renme` `↵` (reveal), right click → **Pin to the top**, **Open data**, then **Rename…** (`F2`) to `renme2` — Expected: the confirmation shows the statement (**PG** `ALTER TABLE "m3"."renme" RENAME TO "renme2"`, **MS** `EXEC [m3db].sys.sp_rename N'[dbo].[renme]', N'renme2'`); after it, the tab and the pin follow the new name.
- [ ] **Truncate…** then **Drop…** — Expected: statement, row estimate, "Nothing depends on it", "yadbe never adds CASCADE"; on a **prod** connection the name must be typed. After the drop the pin is gone. The table tab stays open with its last rows: `F5` there — Expected (known, section 6): **MS** "\"dbo.renme2\" no longer exists…", **PG** only "The database rejected the statement." (details hold the server message).
- [ ] Show DDL (**MY** `kinds`), Properties (rows estimate, sizes, engine, collation, columns, keys).

### Query tools (F-048, F-049, F-052, F-053) — PG, MS, MY

- [ ] `select id, sku, qty from m3.items where qty > :min_qty and sku like :pat order by id` (**MS** `@min_qty`, **MY** `:min_qty`) `⌘↵` — Expected: "Values for 2 query parameters", Run with `3` / `sku-1%` → 2 rows. Run again — values remembered.
- [ ] **Explain** (`⌘L`) on the same text — Expected: parameters asked (prefilled), plan tree with costs and the facts panel. **Explain analyze** (`⌘⌥L`) — "Actual plan" with rows and times.
- [ ] `⇧⌥F` formats; `F12` on a table name reveals it in the explorer; hover a table name — card with its columns.

### Import and export (F-012, F-066, F-091) — PG, MS, MY, SL

- [ ] Right click `m3.imp` → **Import data…** → a `;`-separated CSV with a quoted field holding a comma and accents, one empty `name` and one invalid date — Expected: delimiter found, preview; Columns step "Checked on all N rows", the two problems with their line numbers; **Dry run** "… rows would be written and 2 rejected. ### Activity monitor and EF Core (F-140, F-143) — PG, MS, MY

### Remote and secured connections (F-009, F-010)

- [ ] **pg-ssh** — Expected: database password, then "SSH password for pg-ssh", then "Unknown SSH host key" with the fingerprint → **Trust this key**; connected; `select inet_client_addr()` is the SSH server's side. ## 4. What was checked on Linux, and how

The real app was driven in the Linux container (Ubuntu 24.04, WebKitGTK 2.52, Xvfb with `WEBKIT_DISABLE_COMPOSITING_MODE=1`, no window manager): the debug build with the production CSP (`pnpm tauri build --debug --no-bundle`) for the scenarios, the release build for the measurements, through `tauri-driver` + `WebKitWebDriver` with plain W3C WebDriver requests from Node scripts (in the session's scratch space, not committed). In-page listeners recorded CSP violations (`securitypolicyviolation`), console errors and warnings, uncaught errors and unhandled rejections on every scenario. The GTK file chooser (import, exports, connection export) was driven with `xdotool` (`windowfocus --sync`, Ctrl+L, the path, Return). Every write was verified from `psql`, `sqlcmd`, the `mysql` client or Python's `sqlite3`.

Engines: PostgreSQL 16.15 (native, TLS verify-full with the CA of `dev/tls-certs.sh`), SQL Server 2022 (16.0.4305) and MySQL 8.4.13 in Docker (the MySQL volume recreated so the test user has `PROCESS` and `performance_schema`), SQLite 3.54 files; `dev/mtls.yml` (PostgreSQL 16 on 55433 with `cert` authentication, MySQL 8.4 on 53307 with an x509 user); `dev/ssh-test.sh` (OpenSSH on 2222 / 2223, ssh-agent). Fixtures of section 1 (schemas `m3*`, database `m3db`, databases `yadbe_m3*`).

Secrets: no Secret Service in the container (the keychain status says so), so every password, SSH password, key passphrase and TLS key passphrase was typed in the app's prompts and kept for the session only; none was written to a file or a log. The pgpass import used a fake host and a fake password, in a `~/.pgpass` removed afterwards.

Three quirks of WebKitWebDriver shaped the method (none is an app bug): it sends mouse events but **no pointer events** (tab activation and Radix menus react to `pointerdown`), so the scripts dispatched a `pointerdown` / `pointerup` before the real click, outside grids, and released any pointer capture afterwards (a grid that captured the synthetic pointer otherwise retargets every later real click to itself); it **ignores CSS transforms** when it computes an element's center (floating popovers), so the pointer was moved by viewport coordinates; its keymap **drops Shift** for some characters (`>`, `:`, `_` arrive as `.`, `;`, `-`), so editor text was inserted with `execCommand('insertText')` and field values set through the native setter + `input` event. Real key chords (`Ctrl+Enter`, `Ctrl+S`, `Alt+F12`, `Ctrl+Shift+F`, `Ctrl+Alt+J`…) were sent as WebDriver key actions.

## 6. Bugs and gaps found

No fix was committed by this task: what was found is either larger than a local fix or a deliberate choice to revisit, so each item is written down with its reproduction.

1. **Read-only switched on for an open connection is shown but not enforced** (safety). Edit a connected connection, turn **Read-only** on, Save: the sidebar shows the lock and the status bar "Read-only" at once, but the open session keeps the settings it was opened with (documented on `update_connection` in `src-tauri/src/commands/connections.rs`), so `insert into renme values (9, 'x')` on **sl** ran and committed (verified in the file). The same holds for the statement timeout (a 2 s limit let a 10 s `WAITFOR` finish until a reconnect), keep-alive and TLS settings; the only feedback is the toast "sl saved". Suggested: reconnect (or offer to) when a saved change touches an open session, and until then show what the session runs with.
2. **P-04 regression on WebKitGTK** (section 5): vertical scrolling of the 100k × 50 result at 45–50 fps against 56–59 for the M2 frontend on the same binary. Reproduce with the A/B method of section 5 (`vite build` of each frontend served on port 1420 for a binary built with `cargo build --release`, then `pnpm perf:grid:webkit --binary <it>`). Chromium is unaffected at ×1.
3. **P-01 over target**, one 2.0 MB JS chunk (section 5).
4. **A connection refused for lack of a client certificate** reads "The server rejected the user "yadbe_client" or its password." with **Enter the password**, on a connection that has no password (PostgreSQL `cert` authentication: SQLSTATE 28000 "connection requires a valid client certificate"). `src-tauri/tests/tls_client_cert.rs` asserts on purpose that this is not `tlsClientCertInvalid` (the failure is the server's, not the files'); an error of its own ("the server requires a client certificate", action Edit the connection) would point the right way.
5. **The table tab of a dropped table** stays open with its last rows and "Changed elsewhere: refresh to see it."; `F5` on PostgreSQL shows only "The database rejected the statement." (the server's `relation … does not exist` is in the details) while SQL Server re-describes and says "\"dbo.renme-ms\" no longer exists. Refresh the explorer to see the current objects."
6. **MySQL tables of another database than the connection's** are labelled without it: the result footer "Editable items" and the journal entry "items" for `yadbe_m3re.items` while the connection's own database `yadbe_m3` has an `items` too (the SQL is qualified: `` `yadbe_m3re`.`items` ``). Both labels are `schema.name` (`src/features/result-edit/resultEditModel.ts`, `src/features/journal/journalModel.ts`); MySQL has no schema, so the fix needs a dialect capability, not a front-end engine test.
7. A parameterized statement is recorded in the history as rewritten (`… qty > $1 and sku like $2` on PostgreSQL, `?` on MySQL), without its values — by design (`src-tauri/src/db/params.rs`) — while the "Record the history" hint says statements are saved "exactly as typed". Re-opening it from the history loses the names and the values.
8. Import, Columns step: an empty field read as NULL in a NOT NULL column is reported as `“NULL”`, quoted like a text value.
9. `yadbe file.sql` binds the script to the active tab's connection and connects it at once (a password prompt at launch), whereas a restart never connects by itself. Intended (`src/app/launch.ts`); for the owner to confirm.
10. Still open from the wave notes: the SQL Server import (now 4.9k rows/s) still needs a bulk path; P-07 at ×4; P-09; no single-instance handling for `yadbe file.sql`; no macOS open-with events; MariaDB untested.
