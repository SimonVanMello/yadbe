# Manual validation of milestone M0

Guide to validate M0 on **macOS** and **Windows** before starting M1. Allow about 30 minutes per OS. Section 4 lists what was already checked on Linux and how; section 5 gives the performance measurements.

M0 exit criterion (`docs/PLAN.md`): the app opens, a PostgreSQL or SQLite connection can be created (password in the keychain), tested and opened, and the shell (tabs, sidebar, status bar, statement log, both themes) is in place. There is no SQL editor yet: an open connection shows "The SQL editor opens here".

## 1. Prerequisites

| | macOS | Windows |
|---|---|---|
| OS | macOS 12+ (Intel or Apple Silicon) | Windows 10 (22H2) or 11, x64 |
| Native build tools | Xcode Command Line Tools: `xcode-select --install` | Visual Studio Build Tools 2022, "Desktop development with C++" workload (MSVC + Windows 10/11 SDK) |
| Webview | WKWebView (shipped with the OS) | WebView2 Runtime (preinstalled on Windows 11) |
| Rust | **≥ 1.93** through [rustup](https://rustup.rs) (`rustup update stable`), not Homebrew's Rust | same, `stable-x86_64-pc-windows-msvc` toolchain |
| Node.js | 22.5 or newer (`pnpm perf:startup` uses `node:sqlite`) | same |
| pnpm | 10.x: `corepack enable` (version from `packageManager` in `package.json`) | same |
| PostgreSQL | a server you can reach: local (Postgres.app, Homebrew, Docker) or remote | local (EDB installer, Docker) or remote |

A test database with TLS on is the most useful: `dev/tls-certs.sh` (Git Bash on Windows) creates a throwaway CA and a `localhost` certificate, and `docker compose -f dev/compose.yml up -d` starts PostgreSQL 16 with them on port **55432** (user `yadbe`, password `yadbe-test-pw`, database `yadbe_test`). Also keep a SQLite file at hand (any `.sqlite` / `.db`; `sqlite3 sample.db "create table t(x)"` makes one).

## 2. Running the app

```bash
git clone https://github.com/SimonVanMello/yadbe.git yadbe && cd yadbe
git checkout claude/practical-faraday-39e9km   # until the branch is merged
pnpm install
pnpm tauri dev                              # full app in dev mode (Vite on 1420)
pnpm tauri build --debug --no-bundle        # debug build with the production CSP (nonces), see below
pnpm tauri build --no-bundle                # release binary, used for P-01
```

| | macOS | Windows |
|---|---|---|
| Debug binary | `src-tauri/target/debug/yadbe` | `src-tauri\target\debug\yadbe.exe` |
| Release binary | `src-tauri/target/release/yadbe` | `src-tauri\target\release\yadbe.exe` |
| App database (connections, tabs, preferences) | `~/Library/Application Support/dev.tropico.yadbe/yadbe.db` | `%APPDATA%\dev.tropico.yadbe\yadbe.db` |
| Keychain entries | Keychain Access, service `dev.tropico.yadbe` | Credential Manager → Windows Credentials, `…dev.tropico.yadbe` |

Run the checklist **once with the debug binary** (`tauri dev` has no nonces in its CSP, so a style blocked in production would go unnoticed there). To start from scratch: quit yadbe and delete `yadbe.db`, or use `YADBE_CONFIG_DIR=/an/empty/folder` for an isolated session. Detailed logs: `RUST_LOG=debug`. The web inspector (right click → Inspect, debug builds only) shows CSP violations in its console.

## 3. Checklist

Tick each item; "Expected" describes the correct behavior. OS-specific items are marked **(mac)** or **(win)**. `⌘` on macOS = `Ctrl` on Windows.

### Window and title bar

- [ ] **Startup without flash** — Expected: the window appears directly in the right theme, without a white frame or unstyled content.
- [ ] **Move the window** by dragging an empty area of the title bar (right of the tabs) — Expected: the window follows; dragging a tab reorders it instead.
- [ ] **Double-click** an empty area of the title bar — Expected: **(mac)** zoom per the system setting; **(win)** maximize ↔ restore.
- [ ] **(mac)** Traffic lights — Expected: vertically centered in the title bar, aligned with the tabs, no overlap with the first tab. If off, note by how much (`trafficLightPosition` x 14, y 19 in `src-tauri/tauri.macos.conf.json`).
- [ ] **(mac)** Full screen (green light or ⌃⌘F) — Expected: the tab bar stays usable, the traffic lights disappear cleanly.
- [ ] **(win)** Minimize / Maximize / Close buttons drawn on the right — Expected: they work; the Maximize icon becomes Restore when maximized (also through Win+↑ or snapping). No Snap Layouts flyout on hover (known limit of undecorated windows); Win+←/→ and edge snapping work.
- [ ] **(win)** Resize from every edge and corner — Expected: possible; the 900 × 560 minimum is respected without clipped content.

### Tabs and shortcuts

- [ ] `⌘T` new tab, `⌘1…9` select, `⌃Tab` / `⌃⇧Tab` next / previous, `⌘⇧T` reopen the closed tab — Expected: as named; with a dialog open, no effect.
- [ ] `⌘W` — Expected: closes the active **tab**, never the window; the last tab is replaced by a new one. **(mac) Known risk**: Tauri installs its default macOS menu, whose *File / Window → Close Window* items own ⌘W; if ⌘W closes the window (and quits), report it (follow-up: a yadbe menu like yaggui's).
- [ ] **(mac)** Menu bar — Expected: Tauri's default menu (yadbe, File, Edit, View, Window, Help), in English only. Edit → Copy / Paste / Select All and ⌘C / ⌘V / ⌘A work in the dialog fields. ⌘Q quits.
- [ ] Drag a tab to reorder; right click a tab (pin, close others, move) — Expected: works; the order survives a restart.
- [ ] `⌘B` hides / shows the sidebar, `⌘J` the statement log; drag the panel borders — Expected: smooth; sizes and visibility survive a restart (a change made less than 0.3 s before quitting is not kept, see section 4).

### Connection dialog (F-001, F-004, F-006, F-009)

- [ ] `⌘N` or **New connection** — Expected: dialog with Engine (PostgreSQL, SQL Server, MySQL / MariaDB, SQLite), host / port / database / user / password, Remember password, TLS, name, group, environment, read-only.
- [ ] Paste `postgres://yadbe:yadbe-test-pw@localhost:55432/yadbe_test?sslmode=verify-full&sslrootcert=<path to dev/certs/ca.crt>` into **Connection string** — Expected: the form fills at once; the password field shows "Password from the connection string" (the password itself never comes back to the form).
- [ ] **Test connection** — Expected: "Connected to PostgreSQL 16.x in N ms".
- [ ] Typed errors (change one field, then Test) — Expected message and action button:
  - wrong password → "The server rejected the user … or its password", **Enter the password** (focuses the field);
  - database `nope` → "The database "nope" does not exist on this server", **Edit the connection**;
  - port 5499 → "localhost:5499 refused the connection…", **Edit the connection**;
  - host `no-such-host.invalid` → "The host … could not be found…", **Edit the connection**;
  - TLS *Verify certificate* without the custom CA (remove `sslrootcert` from the string) → "The secure (TLS) connection failed…", **Change the TLS mode**.
- [ ] **Cancel the test** while it runs (host of a machine that drops packets, e.g. a firewalled IP) — Expected: the test stops at once, no error shown.
- [ ] **Remote host with TLS** (a cloud PostgreSQL: RDS, Azure, Supabase…) with *Verify certificate* and no custom CA — Expected: connects using the OS trust store. Not verifiable on the Linux container.
- [ ] Read-only switch — Expected: its hint says it is **not enforced yet** (no statement can run in M0; enforcement is task M2-4).

### Passwords and keychain (F-005)

- [ ] New connection with a typed password and **Remember password** on → Save — Expected: an entry appears in **(mac)** Keychain Access / **(win)** Credential Manager for `dev.tropico.yadbe`; `yadbe.db` has no password column (`sqlite3 yadbe.db .schema connections`).
- [ ] Quit, relaunch, open the connection — Expected: connects without asking. **(mac)** macOS may ask once to allow keychain access: "Always Allow".
- [ ] Connection saved with Remember **off**, open it — Expected: password prompt; a **wrong** password with "Remember" on gives the auth error (toast with **Enter the password**) and stores nothing in the keychain; the right one connects and is stored only then.
- [ ] Remember off: quit and relaunch — Expected: the password is asked again (kept in memory for the session only).
- [ ] Edit a connection whose password is in the keychain — Expected: "A password is stored in the keychain. Type one to replace it."; turning Remember off and saving removes the keychain entry.
- [ ] Delete a connection — Expected: confirmation; its keychain entry is removed too.
- [ ] Paste a connection string with a password, wait **more than 15 minutes**, then Save — Expected: toast "Could not save the connection — The password taken from the connection string expired…" with **Enter the password**; no connection is created; typing the password and saving again creates exactly one connection.

### Opening connections, states and statement log (F-013, F-124)

- [ ] Double-click a connection in the sidebar (or click it on the welcome screen) — Expected: a "Query n" tab bound to it, state dot amber then green, status bar "name · Connected  PostgreSQL 16.x".
- [ ] Statement log (`⌘J` or the status bar) — Expected: `SHOW server_version` (PostgreSQL) or `PRAGMA schema_version` / `SELECT sqlite_version()` (SQLite) with time, duration and row count; the Errors filter; Clear.
- [ ] Kill the server-side session: `psql … -c "select pg_terminate_backend(pid) from pg_stat_activity where usename='yadbe'"` — Expected: the connection comes back by itself (lost → reconnecting → connected in well under a second); a new `SHOW server_version` in the log.
- [ ] Stop the server (`docker compose -f dev/compose.yml stop postgres`) — Expected: amber "Reconnecting (attempt n)…" in the tab, then after ~15 s red "Connection lost" with the refused error; restarting the server does not reconnect by itself; **Connect** does.
- [ ] Disconnect from the connection menu (right click) — Expected: grey dot, "This connection is closed. Connect to start working."

### SQLite (F-002)

- [ ] Welcome → **Open a SQLite file** — Expected: the OS's **native** file dialog, titled "Choose a SQLite database file", filter "SQLite databases" (and "All files"). Picking a file opens the connection dialog with SQLite selected and the path filled. Cancelling the picker still opens the dialog, with an empty path.
- [ ] In the dialog, SQLite → **Browse…** — Expected: same native dialog; the path is replaced.
- [ ] **Test**, **Save**, open — Expected: "Connected to SQLite 3.x", then connected.
- [ ] A path that does not exist — Expected: test fails with "The file "…" does not exist." and **Choose another file** (opens the picker). yadbe never creates the file.
- [ ] **(win)** A path with spaces and accents — Expected: works.

### Themes, language, restore

- [ ] Appearance (⚙) → Light / Dark / System, Language English / Français — Expected: the whole UI switches at once (dialogs, menus, toasts, log); kept across restarts; no flash of the other theme at startup.
- [ ] Open three tabs (two bound to connections, one new tab), activate the second, quit, relaunch — Expected: same tabs, same titles ("Query 1", "Query 2"), same active tab; connections are **not** reopened automatically (the tab offers **Connect**).

## 4. What was checked on Linux, and how

The real app (debug build with the production CSP, and the release build) was driven in the Linux container: Ubuntu 24.04, WebKitGTK 2.52, Xvfb, PostgreSQL 16 with TLS (certificate from `dev/tls-certs.sh`), no window manager. Tooling: `tauri-driver` 2.1 + `WebKitWebDriver` (package `webkit2gtk-driver`), driven with plain W3C WebDriver requests (no client library); in-page listeners recorded CSP violations, console errors and the `connection-state-changed` / `statement-logged` events. The native GTK file chooser was driven with `xdotool`. The real keychain path was exercised with `gnome-keyring-daemon` (Secret Service) in a `dbus-run-session`.

| Checked | Result |
|---|---|
| PostgreSQL from a pasted URL (verify-full + custom CA): test, save, open | ✅ |
| Typed errors: auth, unknown database, refused, DNS, TLS untrusted, TLS name mismatch; actions shown | ✅ (all ~0.2 s) |
| Cancel a running test (server that accepts and never answers) | ✅ stops in < 0.1 s |
| `passwordRequired` → prompt → wrong password (auth error + **Enter the password**) → right password → connected | ✅ |
| Real keychain (gnome-keyring): Remember from the prompt, restart, connects without prompt | ✅ |
| No keychain (no Secret Service): notice in the form and the prompt, session-only, asked again after restart | ✅ |
| `pg_terminate_backend` → lost → reconnecting → connected (~70 ms) | ✅ |
| Cluster stopped → reconnecting attempts 1…5 (1, 2, 4, 8 s) → lost with the refused error and **Edit the connection** | ✅ |
| Event order: `connecting` → statements logged → `connected`; a failed connect emits `closed` with the typed error. The UI takes the state from the events only, so the order of the `connect` reply does not matter | ✅ |
| SQLite through the native picker, test, save, open; statement log | ✅ |
| Held password of a pasted string expired (15 min) before Save | ✅ after the fix (no duplicate, see below) |
| Tabs (titles, ordinals, active tab), layout and theme across a restart | ✅ |
| Layout change < 300 ms before closing the window | ❌ not kept (debounce not flushed on close; accepted for M0) |
| `uiState` size | ~100 bytes (limit 64 KiB) |
| CSP of the debug build (nonces): dialogs, menus, popovers, toasts, picker | ✅ no violation after the fix |
| Undecorated window, drawn buttons, window shown once restored; Close quits | ✅ (maximize / snap need a window manager: not checked) |

Gaps found and fixed during this check (task M0-4):

- **CSP**: Radix's scroll lock (`react-remove-scroll-bar`, used by modal dialogs) injected a `<style>` without the page nonce, blocked in production builds. The nonce is now handed over through `get-nonce` at startup (`src/ui/cspNonce.ts`).
- **SQLite file picker**: the real app had none (Browse was hidden). Native open dialog through `tauri-plugin-dialog`, permission `dialog:allow-open` only, exposed as `src/ipc/fileDialog.ts` with a browser stand-in in the mock.
- **Expired held password**: Save created the connection, then failed to store the password; the dialog stayed open and a second Save created a duplicate. The connection is now deleted again when its password cannot be stored, the form drops the expired held password, and the toast offers **Enter the password**.
- **Wording**: the SQLite file hint said the file "is created if it does not exist" (the backend refuses missing files on purpose); the read-only hint claimed writes are refused although nothing enforces it yet.

Not verifiable here (to check on macOS / Windows): real macOS Keychain and Windows Credential Manager, the macOS traffic lights overlay and default menu (⌘W), Windows drawn buttons, maximize / snap and resize, native file dialog look and modality, TLS to a remote host with the OS trust store, first-launch cost of WKWebView / WebView2.

## 5. Performance measurements

Reproducible method, to run again on the reference machine:

```bash
pnpm tauri build --no-bundle
pnpm perf:startup        # P-01: 10 starts per scenario (headless Linux: xvfb-run -a pnpm perf:startup)
pnpm perf:tabs           # P-07: 60 tab switches, production build of the front on the mocked backend
```

- **P-01** (`scripts/measure-startup.mjs`): launches the release binary with `YADBE_PERF_PROBE=1`. The window starts hidden; the frontend shows it once preferences, layout and the restored tabs are rendered, and the probe records when it becomes visible, then quits. Time is measured from the process `spawn` (executable loading, webview creation, JS boot, restore). Two scenarios: `welcome` (empty config) and `restore` (one SQLite connection, three restored query tabs). `--drop-caches` (Linux, root) drops the disk cache before each launch.
- **P-07** (`e2e/perf.spec.ts`, `playwright.perf.config.ts`): three tabs bound to connections; from the ⌃1/⌃2/⌃3 `keydown` to the next painted frame, checking the right tab is shown. Measurement floor: one frame (~16.7 ms at 60 Hz). Also run with a 4× CPU slowdown. The same measurement was run inside the real app (WebKitGTK) through WebDriver.

Results in the Linux container (Xvfb, software rendering, WebKitGTK 2.52; **not** the reference machine of SPEC §3):

| Measure | Scenario | Median | Min – max | Target |
|---|---|---|---|---|
| P-01 start → interactive window | welcome, empty config (10 launches, disk cache dropped before each) | **630 ms** | 538 – 1,163 ms | < 800 ms ✅ |
| P-01 | restore: 1 SQLite connection, 3 tabs (10 launches, disk cache dropped) | **602 ms** | 535 – 655 ms | < 800 ms ✅ |
| P-01 | warm disk cache, welcome / restore | 535 / 510 ms | 467 – 595 ms | < 800 ms ✅ |
| P-07 tab switch (3 bound tabs, 60 switches) | production front on the mock, Chromium | **21 ms** (p95 27–30 ms) | max 31–39 ms | < 50 ms ✅ |
| P-07 | same, 4× CPU slowdown | 39–96 ms (p95 72–155 ms) | max 85–214 ms | indicative |
| P-07 | real app (release, WebKitGTK), same measurement through WebDriver | **17 ms** (p95 24 ms) | max 32 ms | < 50 ms ✅ |

Of the P-01 time, ~30–60 ms pass before `run()` starts (loading the 27 MB binary and the GTK / WebKit libraries); the rest is webview creation, JS boot and restore. The first launch after a build is the slowest (WebKitGTK creates its caches). A tab switch also saves the tabs (`save_tabs`, one SQLite write, asynchronous): it is not on the measured path. The 4× slowdown figures vary a lot from run to run in this container.

On macOS / Windows, include the output of `pnpm perf:startup` and `pnpm perf:tabs` in the report.

## 6. Reporting a problem

For each failing item, write down:

1. **OS and version** (e.g. macOS 15.1 Apple Silicon, Windows 11 24H2) and mode (`pnpm tauri dev`, debug or release binary).
2. **The checklist item** (copy the line).
3. **Steps** to reproduce, from launch.
4. **Expected / actual**, one sentence each.
5. **Screenshot** (mac: ⌘⇧4; win: Win+⇧+S) or a short video for motion issues.
6. For an error: the toast **Details** and the statement log entry. For a crash: the terminal output with `RUST_LOG=debug`.
