# Manual validation of milestone M2 (MVP)

Guide to validate M2 on **macOS** and **Windows** before starting M3. Allow about 2 h per OS (three engines). The edit-safety scenarios come first: they are the reason this milestone exists. Section 4 lists what was already checked on Linux and how, with the gaps found and fixed; section 5 gives the performance measurements; section 6 what could not be verified here.

M2 exit criterion (`docs/PLAN.md`): table data is browsed, filtered and edited safely with a SQL preview; production connections are protected; autocomplete, palette, export and preferences make it usable daily.

The M0 and M1 checklists (`docs/validation/M0.md`, `M1.md`) still apply to the shell, the connections, the explorer and the query tabs.

## 1. Prerequisites

Same toolchain and engines as M1 (`docs/validation/M1.md`, section 1). Then load the edit fixtures, which have one table per situation: `kinds` (one column per value kind, defaults, an identity), `composite` (two-column key), `Odd "Table"` (identifiers that need quotes), `items` (unique, check, generated column), `child` (foreign key to `items`), `keyless`, `uniq` (identity through a unique key), `items_view`, and on SQL Server `audited` (a trigger that inserts into `audit_log`).

```bash
# PostgreSQL: schema m2
PGPASSWORD=yadbe-test-pw psql -h localhost -p 55432 -U yadbe -d yadbe_test -c "create schema m2"
sed 's/{s}/m2/g' src-tauri/tests/fixtures/edit_postgres.sql \
  | PGPASSWORD=yadbe-test-pw psql -h localhost -p 55432 -U yadbe -d yadbe_test -v ON_ERROR_STOP=1 -q
PGPASSWORD=yadbe-test-pw psql -h localhost -p 55432 -U yadbe -d yadbe_test -v ON_ERROR_STOP=1 -q <<'SQL'
insert into m2.kinds(flag, small, big, amount, label, day, ref, doc, mood)
  select g % 2 = 0, g, 9007199254740993 + g, 12345678901234567890.0123456789, 'label ' || g,
         date '2026-01-01' + g, gen_random_uuid(), jsonb_build_object('n', g), 'ok'
  from generate_series(1, 20) g;
insert into m2.items(sku, qty, price) select 'sku-' || g, g % 5, g + 0.5 from generate_series(1, 40) g;
insert into m2.child values (1, 1);
insert into m2.composite select g, 'b' || g, 'v' || g from generate_series(1, 5) g;
insert into m2."Odd ""Table""" values (1, 'sel', 'two');
insert into m2.keyless values ('a', 1);
create table m2.big as select g as id, 'row ' || g as label, (g * 1.25)::numeric(14,2) as amount,
  9007199254740993::bigint + g as big from generate_series(1, 1000000) g;
alter table m2.big add primary key (id);
analyze m2.big;
create function m2.w() returns int language sql as 'insert into m2.keyless values (''w'', 9) returning 1';
SQL
# SQL Server: database m2db (schema edits)
docker exec yadbe-test-engines-mssql-1 /opt/mssql-tools18/bin/sqlcmd -C -I -S localhost -U sa -P Yadbe-test-pw1 -Q "CREATE DATABASE m2db"
docker cp src-tauri/tests/fixtures/edit_mssql.sql yadbe-test-engines-mssql-1:/tmp/edit.sql
docker exec yadbe-test-engines-mssql-1 /opt/mssql-tools18/bin/sqlcmd -C -I -S localhost -U sa -P Yadbe-test-pw1 -d m2db -i /tmp/edit.sql
#   then a few rows: INSERT INTO edits.items(sku, qty, price) VALUES (N'sku-1', 1, 1.5), (N'sku-2', 2, 2.5); INSERT INTO edits.child VALUES (1, 1); …
# A read-only SQL Server database for error 3906:
#   CREATE DATABASE m2ro; then in m2ro: CREATE TABLE dbo.t (id int PRIMARY KEY, v nvarchar(20)); INSERT INTO dbo.t VALUES (1, N'a'); then ALTER DATABASE m2ro SET READ_ONLY
# SQLite
sqlite3 m2.db < src-tauri/tests/fixtures/edit_sqlite.sql
sqlite3 m2.db "insert into items(sku, qty, price) values ('sku-1', 1, 1.5), ('sku-2', 2, 2.5); insert into child values (1, 1);"
```

Connections: **pg**, **mssql** (database `m2db`), **sqlite** (`m2.db`), as in M1; then **pg prod** (a duplicate tagged prod, not read-only) and **pg prod ro**, **mssql prod ro**, **sqlite prod ro** (read-only, prod). Keep a second client open on each engine (psql, sqlcmd / Azure Data Studio, sqlite3): every "verify" below means *from that client*, not from yadbe.

Drop it all afterwards: `drop schema m2 cascade`, `DROP DATABASE m2db` / `m2ro` (`ALTER DATABASE m2ro SET READ_WRITE` first), delete `m2.db`.

## 2. Running the app

As in M1: the checklist with the debug build with the production CSP (`pnpm tauri build --debug --no-bundle`) and the web inspector open (right click → Inspect: CSP violations and console errors), the measurements of section 5 with the release build. `⌘` on macOS = `Ctrl` on Windows. **PG**, **MS**, **SL** mark the engines a line applies to.

## 3. Checklist

### Edit safety first (F-082 to F-086) — PG, MS, SL

Open each table by double-clicking it in the explorer, or `⌘K`, type its name, `⇧↵` (Open data).

- [ ] `kinds`: double-click a cell of each kind and change it: text (accents, a quote `'`), smallint, **bigint** `9223372036854775807` (**MS** also `-9223372036854775808`), **numeric with 30 digits** `99999999999999999999.9999999999`, float, boolean (choice editor: true / false / NULL), date, time, timestamp with 6 decimals, timestamptz / datetimeoffset with an offset, uuid, JSON (multi-line editor: `⌘↵` commits, `↵` is a new line), enum (**PG** `mood`: list), binary (hex). `⌘⌫` on a cell sets NULL; clearing a text cell gives an empty string. — Expected: each edited cell turns "modified"; the toolbar says "N pending"; NULL shows as `NULL`, the empty string as `empty`. A JSON value with 20 digits keeps them all.
- [ ] Array (**PG** `tags`), `spot` (point), generated / identity / rowversion (**MS** `version`, `variant`) columns — Expected: a lock in the header, the reason on hover, not editable.
- [ ] **Preview SQL** — Expected: the transaction, one `UPDATE … WHERE "id" = …` per row, values written as literals (`'x''y'`, `N'…'` on MS, `'\xcafe'` / `0xCAFE` for binary), the connection banner. `⌘S` inside the dialog applies (the button shows it). Verify from the other client: every value exactly as typed (timestamptz converted by the server); the grid now shows the **server's** values.
- [ ] `⌘I` (Insert row) on `kinds`: set two columns only, `⌘D` (Duplicate) an existing row, select rows and `⌘⌦` (Delete; on a Mac keyboard: `fn⌘⌫`), paste two TSV lines (right click → Paste rows) — Expected: new rows show `DEFAULT` in untouched columns, deleted rows are struck through. Apply → verify: the identity, the defaults (`note = 'hello'`, `created`) and the generated columns (`items.total`) come back in the grid. **MS** `audited` (trigger): insert a row → Expected: applied, its `id` shown (the trigger's own row counts do not confuse the one-row check).
- [ ] **Rollback, nothing lost**: in `items`, change `qty` of two rows; from the other client delete the second row; Apply → Expected: "Nothing was applied: the transaction was rolled back · statement 2 failed", "The row id = 2 was changed or deleted by someone else…", the row marked failed, both changes still pending, the first row unchanged in the database. **Revert this change** then Apply → only the first change lands.
- [ ] Constraint violations, each rolled back with the constraint named (**SL** names the column for unique / not-null, no name for foreign keys): unique (`sku` = an existing one), check (`qty` = -1), not null (insert a row without `sku`), foreign key (`child.item_id` = 99999; **SL** too: yadbe turns `foreign_keys` on, see the statement log at connect: `PRAGMA foreign_keys = ON`). An invalid value (`qty` = `abc`) is refused in the editor ("Not an integer.") before anything is sent.
- [ ] `composite`: edit `value` → Expected: `WHERE "a" = … AND "b" = …`. `Odd "Table"`: edit `Select` and `two words` → Expected: `"Odd ""Table"""` / `[Odd "Table"]`, `"Select"`, `"two words"` quoted; verify.
- [ ] `keyless` — Expected: "Read-only. This table has neither a primary key nor a unique key on non-null columns…", no editing. `uniq` (unique non-null key) — editable. `items_view` — "A view cannot be edited from its rows." A read-only connection (`… prod ro`) — "The connection is read-only.", Insert row disabled, rows shown.
- [ ] Close a table tab with pending changes (`⌘W`) — Expected: "Discard N pending changes?" with the connection banner; Cancel keeps the tab. Refresh (`F5`), change page, filter or sort with pending changes — the same question.

### Production connections (F-008, F-051, F-085)

- [ ] **pg prod**: an edit, Apply — Expected: the preview always opens (its "Always preview" switch is not offered), red **Production connection** note and a red Apply button.
- [ ] **pg prod**: `delete from m2.keyless` in a query tab — Expected: "Run a potentially destructive statement?" with the banner `pg prod · PROD`; the guard cannot be turned off for prod.
- [ ] **pg prod ro**: `select m2.w()` — Expected: refused by the server, "cannot execute INSERT in a read-only transaction" and "This connection is read-only: the database refused this statement…". **MS** on **mssql** (read-write) `UPDATE m2ro.dbo.t SET v = N'b' WHERE id = 1` — Expected: "The database is read-only: it refused this statement…", no "Edit the connection" action.
- [ ] A result paused at its cap, wait 30 s, Cancel — Expected: the final time excludes the pause.

### Browsing (F-080, F-081)

- [ ] `m2.big` (1M rows) — Expected: first page at once, "Rows 1–500", "≈ 1,000,000 rows". Page size 5 000, next / previous page (`Alt+PageDown` / `Alt+PageUp`). A small table (`kinds`) shows its exact count at once (the last page says it).
- [ ] Exact count: WHERE `pg_sleep(0.00002) is not null` (**PG**; **MS** a cross join in a subquery), **Count**, then **Cancel** — Expected: stops within a second; the server shows no running query.
- [ ] Filter chips (`⌘F` on the grid opens the form): one condition of each family — `=` / `≠`, `<` `≤` `>` `≥`, contains / starts with / ends with (`%` and `_` taken literally), in (one value per line), between, is null / is not null — combined, values bound (statement log: the literals appear only in the log). Raw WHERE `qty > 2` combined with chips; a broken one (`nope === 1`) — Expected: the engine's error under the field, rows kept. On a read-only connection, a raw WHERE that writes (`1 = 1) DELETE FROM items WHERE (1 = 1`) is refused.
- [ ] Multi-column sort: click a header, `⇧`-click a second, again to reverse — Expected: arrows with the key number; pages stay stable (the key breaks ties).

### Autocomplete (F-043)

- [ ] **PG** `select * from kin` → `m2.kinds` offered and inserted qualified (`m2` is not in `search_path`); `select * from kinds` with `set search_path = m2, public` first → unqualified. `select * from m2.Od` → inserts `m2."Odd ""Table"""`. `select k.| from m2.kinds k` → the columns of `kinds`. `select * from m2.child c join m2.items i on |` → first suggestion `i.id = c.item_id` (Foreign key).
- [ ] **MS** `select * from it` → `edits.items` (default schema `dbo`: other schemas are qualified, `[ ]` where needed). **SL** no schema: `select * from ki` → `kinds`.
- [ ] Run `create table m2.newt(x int)`, refresh the schema in the explorer (or `F5` on it) → `m2.newt` is offered. (Without a refresh it is not: no automatic refresh after DDL yet.)

### Palette (F-120, F-121)

- [ ] `⌘K` (and `⌘P`): `>` actions (e.g. "Export the table…", "Preferences"), `:` connections (connect), `@` objects: `↵` reveals the object in the explorer (expands down to it), `⌘↵` Script as SELECT, `⇧↵` opens its data; `#` tabs; `!` history. Objects of every connected connection, system objects left out.

### Export (F-066)

- [ ] **PG** `select g, 'row ' || g, 9007199254740993::bigint + g from generate_series(1, 1000000) g` → paused at 100,000 → `⌘⇧E` → CSV → native save dialog → Expected: toast "Exported 1,000,000 rows · … MB"; the file has 1,000,001 lines (header), UTF-8, big numbers exact. JSON (array, "Numbers when exact") → `big` values are strings, others numbers.
- [ ] Export the same result again — Expected: the dialog says only the rows kept in the grid are exported (the rest went to the first export); the result reads `100,000+`.
- [ ] Table tab: filter + sort, **Export the table…** (download icon in the strip, or right click → Export…) — Expected: the dialog says only the filtered rows go, and that pending changes are not in the file; the file holds every matching row in the tab's order, not only the page.
- [ ] Cancel a long export from its toast — Expected: no file left (no `.…yadbe-N.tmp` either).

### Preferences (F-125)

- [ ] `⌘,`: Theme, Language, Density (compact rows), Interface text size, Editor font / size, Grid font / size — Expected: applied at once; the grid columns re-fit to the new font (no cut values). NULL text `∅` — the grid shows it, exports still write NULL. Rows kept per result 1 000 → a query pauses at 1,000. Preview before applying off (non-prod) → Apply applies directly. Record the history off → statements no longer appear; on again. Connect timeout 3 s → a host that accepts TCP but never answers (`python3 -c "import socket;s=socket.socket();s.bind(('127.0.0.1',55999));s.listen();input()"`) fails after 3 s with "did not answer within 3 s" on **PG** and **MS**.

### Restart

- [ ] Quit with query tabs and table tabs (with a filter and a sort) on the three engines, relaunch — Expected: the same tabs; table tabs say "Connect to see and edit its rows." and do not connect by themselves; once connected, filter and sort are back.

## 4. What was checked on Linux, and how

The real app was driven in the Linux container (Ubuntu 24.04, WebKitGTK 2.52, Xvfb with `WEBKIT_DISABLE_COMPOSITING_MODE=1`), debug build with the production CSP for the checklist and the release build for the measurements, through `tauri-driver` + `WebKitWebDriver` with W3C WebDriver: real key chords and mouse clicks (actions API), in-page listeners for CSP violations (`securitypolicyviolation`), console errors / warnings and unhandled rejections. The GTK file chooser was driven with `xdotool` (`windowfocus --sync`, Ctrl+A, the path, Return). Engines: PostgreSQL 16.15 (TLS verify-full with the CA of `dev/tls-certs.sh`), SQL Server 2022 (16.0.4305) in Docker, SQLite files, loaded with the fixtures of section 1 (schema `m29`, database `m29db`, dropped afterwards). Every applied change was verified from `psql`, `sqlcmd` or Python's `sqlite3`. No keychain in the container: passwords were session-only.

Gaps found and fixed (task M2-9):

- **`⌘S` did nothing in Preview SQL** although its Apply button shows it: global shortcuts are off while a dialog is open. The dialog now listens itself.
- **Misleading estimate**: a never-analyzed PostgreSQL table of 22 rows read "Rows 1–22 · ≈ 220 rows". A last page gives the exact count, shown instead.
- **A result drained by an export** (rows past the cap written to the file only) then read "100,000 rows", complete; a second export silently wrote 100,000 rows (the toast said so afterwards). `ResultSummary.truncated` now keeps the `+`, the grid footer says where the rest went, the export dialog warns first.
- **Grid font preferences**: columns kept their widths after a font change, cutting values. They re-fit (except the ones the user resized).
- **SQL Server connect timeout** reported as a TLS failure (tiberius' timeout message names the TLS negotiation). Now "did not answer within N s".
- **SQL Server error 3906** (read-only database) said "This connection is read-only" with "Edit the connection" on a read-write connection. Own message now.
- Known items of the task: SQLite foreign keys enforced (`PRAGMA foreign_keys = ON` per connection, in the statement log); the autocomplete reads the palette's catalog cache (one read per connection and database); NULL cells are measured with the NULL text preference; table export (backend `ExportSourceSpec::Table`, UI, mock, tests on the three engines); Playwright tests for `⌘F` and the `tableDataChanged` notice.

Observed, not changed (follow-ups):

- No automatic refresh of the explorer / autocomplete after DDL run in a query tab: a manual refresh is needed.
- A row changed (not deleted) by another session is overwritten without notice: optimistic concurrency is F-089 (V1).
- `tableDataChanged` cannot fire from the UI today (one tab per table); it will with editable results (F-087).
- Run is disabled while a result is paused at its cap: Cancel (or Load more / all) first.
- A new row shows `DEFAULT` in a NOT NULL column without default; the server then refuses the insert (rolled back, clear message). An earlier hint would be nicer.
- Table export pages with `OFFSET` (about 150 000 rows/s against 430 000 for a result); keyset paging or a snapshot transaction would be faster and consistent.
- P-07 at CPU ×4: 90 ms median (45 ms before M2); at ×1 it meets the target.
- A completion popup with the statement keywords showed once after a run on a freshly connected tab; not reproduced.
- Setting hints such as "Off, no statement is recorded." read as if the switch were off.

## 6. Not verifiable here

macOS (WKWebView) and Windows (WebView2): the shortcut table of section 3, native dialogs, real keychains, IME in cell editors and the editor, clipboard paste of rows (`navigator.clipboard.readText` permission), GPU scrolling, RAM of the webview (P-09). Azure SQL, named instances and Windows authentication. Fonts installed on the OS for the font preferences (only DejaVu here). Large real-world schemas for autocomplete beyond the synthetic 10k-object catalog.
